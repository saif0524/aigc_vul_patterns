# Replication Guide

This document provides step-by-step instructions to reproduce all results reported in the paper *"Beyond Static Analysis: Why Algorithmic AI Code Generation Requires Runtime Sanitization"*.

## Prerequisites

### System Requirements

- **OS**: Ubuntu 22.04+ (tested on Ubuntu 24.04.3 LTS)
- **Compiler**: g++ 13.3.0 or later (C++17 support required)
- **Python**: 3.11+
- **Disk**: ~50 GB (for binaries, analysis outputs, and sanitizer logs)
- **RAM**: 16 GB minimum (sanitizer-instrumented binaries use more memory)

### Software Dependencies

Install system-level tools:

```bash
# Compiler and build tools
sudo apt-get install g++ build-essential

# Static analysis
sudo apt-get install cppcheck                     # v2.19.0
sudo apt-get install clang-tidy-21                # clang-tidy v21

# Python
sudo apt-get install python3.11 python3.11-venv
```

Install Python packages:

```bash
pip install pandas numpy scipy matplotlib seaborn pyarrow jupyter
```

### Verify Tool Versions

```bash
g++ --version          # Expected: g++ (Ubuntu 13.3.0-...) 13.3.0
cppcheck --version     # Expected: Cppcheck 2.19.0
clang-tidy-21 --version # Expected: LLVM version 21.*
python3.11 --version   # Expected: Python 3.11.*
```

## Replication Steps

### Step 0: Clone and Verify Data Integrity

```bash
git clone <repository-url>
cd aigc_vul_patterns
```

All data in `data/` is frozen. The dataset originates from google-deepmind/code_contests at commit `fa7a4f8139aab08362503f3344778eb86901709a` (October 2025). AI-generated code was produced via the OpenRouter API during the same period. See [DATA.md](DATA.md) for full provenance.

### Step 1: Extract C++ Source Files

Extract C++ source code from the JSON generation files into individual `.cpp` files:

```bash
python3.11 scripts/extract_cpp.py
python3.11 scripts/extract_cpp_human.py
```

**Output**: `derived/cpp/{gemma,llama,qwen,human}/` — one `.cpp` file per generated program.

This step applies the regex-based extraction described in the paper (Section 5, Extraction and Preprocessing). Responses without a valid fenced C++ code block are excluded.

### Step 2: Compile and Test (Functional Correctness)

Compilation and testing are performed together. The script compiles each `.cpp` file with `g++ -std=c++17 -O2`, then runs it against the public test cases:

```bash
python3.11 scripts/run_tests_parallel.py
```

- **Compilation**: `g++ -std=c++17 -O2` per file → binaries in `bin/{gemma,llama,qwen,human}/`
- **Test timeout**: 10 seconds per test case
- **Output**: `analysis/tests/` (per-file results)
- **Records**: compile status, number of tests passed, total tests, pass/fail, timeouts
- Programs that fail to compile are recorded but excluded from test execution and dynamic analysis

### Step 3: Static Analysis — Cppcheck

Run cppcheck on all extracted source files:

```bash
python3.11 scripts/run_cppcheck_parallel.py
```

- **Configuration**: `--enable=warning,style,performance,portability --inconclusive --std=c++17`
- **Timeout**: 30 seconds per file
- **Output**: XML reports in `analysis/cppcheck/`

Parse XML reports into CSV:

```bash
python3.11 scripts/parse_cppcheck.py
```

**Output**:
- `results/raw_csv/cppcheck_detailed.csv` — per-warning granularity with CWE mapping
- `results/raw_csv/cppcheck_summary.csv` — per-program summary

### Step 4: Static Analysis — Clang-tidy

```bash
./scripts/run_clang_tidy.sh --mode full
```

- **Checks**: `clang-analyzer-*`, `bugprone-*`, `performance-*`, `modernize-*`
- **Standard**: C++17
- **Output**: YAML reports in `analysis/clang_tidy/`

Parse YAML reports:

```bash
python3.11 scripts/parse_clang_tidy.py
```

**Output**: `results/raw_csv/clang_tidy_detailed.csv`, `results/raw_csv/clang_tidy_summary.csv`

### Step 5: Dynamic Analysis — ASan/UBSan

Compile with sanitizer instrumentation and execute:

```bash
python3.11 scripts/run_sanitizers.py
```

- **Compilation**: `g++ -std=c++17 -O1 -fsanitize=address,undefined -fno-omit-frame-pointer`
- **Execution**: Same test inputs as Step 2
- **Output**: Sanitizer logs in `analysis/sanitizers/`

Parse sanitizer output:

```bash
python3.11 scripts/parse_sanitizers.py
```

**Output**:
- `results/raw_csv/sanitizer_detailed.csv` — per-error records with CWE classification
- `results/raw_csv/sanitizer_summary.csv` — per-program trigger summary

### Step 6: Merge All Results

Combine all tool outputs into a unified master CSV:

```bash
python3.11 scripts/merge_master_all.py
```

**Output**: `results/raw_csv/master_analysis.csv` — one row per program with columns for:
- Compilation status, test pass rate, pass/fail
- Cppcheck CWE counts and categories
- Clang-tidy diagnostic counts
- Sanitizer trigger status and error types
- Problem tags and metadata

### Step 7: Generate Tables and Figures

Open and run the analysis notebooks:

```bash
jupyter notebook notebooks/results.ipynb
```

This notebook generates all tables in `results/tables/` and figures in `results/figures/` reported in the paper, including:

| Paper Reference | Output File |
|----------------|-------------|
| Table 2 (Baseline CWE prevalence) | Computed inline from `master_analysis.csv` |
| Table 3 (MITRE Top-25) | `results/tables/q5_top10_cwe_with_severity.csv` |
| Table 4 (Multi-tier summary) | `results/tables/verification_tool_summary.csv` |
| Table 5 (Sanitizer by generation) | `results/tables/san_trigger_rate_by_model_gen.csv` |
| Figure 2 (CWE type distributions) | `results/figures/cwe_type_dist_{model}.pdf` |
| Figure 3 (Sanitizer CWE distribution) | `results/figures/san_cwe_distribution.pdf` |
| Figure 4 (Sanitizer trigger rates) | `results/figures/san_trigger_rate_by_model.pdf` |
| Figure 5 (CWE by pass/fail status) | `results/figures/cwe_by_status.pdf` |

### Step 8: Statistical Tests

The two-proportion z-test (z = 9.28, p < 0.001) and the sanitizer cross-tabulation by pass/fail status are computed in:

```bash
jupyter notebook notebooks/reviewer_response_executed.ipynb
```

This notebook also generates `results/tables/san_trigger_by_pass_status.csv`.

## Troubleshooting

**Cppcheck version mismatch**: CWE mappings may differ between cppcheck versions. Use v2.19.0 for exact replication.

**Clang-tidy not found**: On Ubuntu, install via `sudo apt-get install clang-tidy-21`. The script expects the binary named `clang-tidy-21`.

**Sanitizer out-of-memory**: ASan increases memory usage ~2x. If a program OOMs under sanitizer, it is recorded as a sanitizer event. Ensure at least 16 GB RAM.

**Test timeout differences**: Minor variations in pass rates may occur on different hardware due to the 10-second timeout boundary. This does not affect sanitizer or static analysis results.
