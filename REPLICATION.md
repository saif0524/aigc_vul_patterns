# Replication Guide

This document provides step-by-step instructions to reproduce all results reported in the paper *"Evaluating the Security of AI-Generated C++ Code: An Empirical Comparison with Human Baselines"* (ICSME 2026).

## Prerequisites

### System Requirements

- **OS**: Ubuntu 22.04+ (tested on Ubuntu 24.04.3 LTS)
- **Compiler**: g++ 13.3.0 or later (C++17 support required)
- **Python**: 3.11+
- **Disk**: ~50 GB (binaries, analysis outputs, sanitizer logs, and ESBMC JSON results)
- **RAM**: 16 GB minimum (sanitizer-instrumented binaries use ~2× memory; ESBMC runs in parallel)

### Software Dependencies

Install system-level tools:

```bash
# Compiler and build tools
sudo apt-get install g++ build-essential

# Static analysis
sudo apt-get install cppcheck                     # v2.19.0
sudo apt-get install clang-tidy-21                # clang-tidy v21

# Python
sudo apt-get install python3.11 python3.11-venv
```

Install Python packages:

```bash
pip install pandas numpy scipy matplotlib seaborn pyarrow jupyter
```

### ESBMC Binary (Formal Verification — Step 8)

ESBMC must be installed separately. Download the pre-built binary for Ubuntu:

```bash
mkdir -p esbmc/bin
# Download from https://github.com/esbmc/esbmc/releases (v8.0.0)
wget -O esbmc/bin/esbmc <release-url-for-ubuntu-binary>
chmod +x esbmc/bin/esbmc
```

The scripts expect the binary at `esbmc/bin/esbmc` relative to the repository root.

### Verify Tool Versions

```bash
g++ --version           # Expected: g++ (Ubuntu 13.3.0-...) 13.3.0
cppcheck --version      # Expected: Cppcheck 2.19.0
clang-tidy-21 --version # Expected: LLVM version 21.*
python3.11 --version    # Expected: Python 3.11.*
esbmc/bin/esbmc --version # Expected: ESBMC version 8.0.0*
```

## Replication Steps

### Step 0: Clone and Verify Data Integrity

```bash
git clone <repository-url>
cd aigc_vul_patterns
```

All data in `data/` is frozen. The dataset originates from google-deepmind/code_contests at commit `fa7a4f8139aab08362503f3344778eb86901709a` (October 2025). AI-generated code was produced via the OpenRouter API during the same period. See [DATA.md](DATA.md) for full provenance.

### Step 1: Extract C++ Source Files

Extract C++ source code from the JSON generation files into individual `.cpp` files:

```bash
python3.11 scripts/extract_cpp.py
python3.11 scripts/extract_cpp_human.py
```

**Output**: `derived/cpp/{gemma,llama,qwen,human}/` — one `.cpp` file per generated program.

This step applies the regex-based extraction described in the paper (Section 5, Extraction and Preprocessing). Responses without a valid fenced C++ code block are excluded.

### Step 2: Compile and Test (Functional Correctness)

Compilation and testing are performed together. The script compiles each `.cpp` file with `g++ -std=c++17 -O2`, then runs it against the public test cases:

```bash
python3.11 scripts/run_tests_parallel.py
```

- **Compilation**: `g++ -std=c++17 -O2` per file → binaries in `bin/{gemma,llama,qwen,human}/`
- **Test timeout**: 10 seconds per test case
- **Output**: `analysis/tests/` (per-file results)
- **Records**: compile status, number of tests passed, total tests, pass/fail, timeouts
- Programs that fail to compile are recorded but excluded from test execution and dynamic analysis

### Step 3: Static Analysis — Cppcheck

Run cppcheck on all extracted source files:

```bash
python3.11 scripts/run_cppcheck_parallel.py
```

- **Configuration**: `--enable=warning,style,performance,portability --inconclusive --std=c++17`
- **Timeout**: 30 seconds per file
- **Output**: XML reports in `analysis/cppcheck/`

Parse XML reports into CSV (called automatically by `run_full_analysis.py`, or manually):

```bash
python3.11 scripts/parse_tests.py   # also triggers cppcheck CSV generation
```

**Output**:
- `results/raw_csv/cppcheck_detailed.csv` — per-warning granularity with CWE mapping
- `results/raw_csv/cppcheck_summary.csv` — per-program summary

### Step 4: Static Analysis — Clang-tidy

```bash
./scripts/run_clang_tidy.sh --mode full
```

- **Checks**: `clang-analyzer-*`, `bugprone-*`, `performance-*`, `modernize-*`
- **Standard**: C++17
- **Output**: YAML reports in `analysis/clang_tidy/`

Parse YAML reports:

```bash
python3.11 scripts/parse_clang_tidy.py
```

**Output**: `results/raw_csv/clang_tidy_detailed.csv`, `results/raw_csv/clang_tidy_summary.csv`

### Step 5: Dynamic Analysis — ASan/UBSan

Compile with sanitizer instrumentation and execute:

```bash
python3.11 scripts/run_sanitizers.py
```

- **Compilation**: `g++ -std=c++17 -O1 -fsanitize=address,undefined -fno-omit-frame-pointer`
- **Execution**: Same test inputs as Step 2
- **Output**: Sanitizer logs in `analysis/sanitizers/`

Parse sanitizer output:

```bash
python3.11 scripts/parse_sanitizers.py
```

**Output**:
- `results/raw_csv/sanitizer_detailed.csv` — per-error records with CWE classification
- `results/raw_csv/sanitizer_summary.csv` — per-program trigger summary

### Step 6: Parse All Tool Outputs

```bash
python3.11 scripts/parse_tests.py
python3.11 scripts/parse_clang_tidy.py
python3.11 scripts/parse_sanitizers.py
```

### Step 7: Merge All Results

Combine all tool outputs into a unified master CSV:

```bash
python3.11 scripts/merge_master_all.py
```

**Output**: `results/raw_csv/master_analysis.csv` — one row per program with columns for:
- Compilation status, test pass rate, pass/fail
- Cppcheck CWE counts and categories
- Clang-tidy diagnostic counts
- Sanitizer trigger status and error types
- Problem tags and metadata

### Step 8: Formal Verification — ESBMC (Three Configurations)

ESBMC is run in three configurations to study the effect of property set and unwind depth on cross-tool agreement. Each configuration writes to its own tagged output directory and CSV prefix.

**Prerequisites**: ESBMC binary installed at `esbmc/bin/esbmc` (see Prerequisites section).

#### Config A — Baseline (no overflow-check, reproduces original paper results)

```bash
python3.11 scripts/run_esbmc.py \
    --mode full --jobs 8 --only all \
    --no-overflow-check \
    --unwind 10 --timeout 60 \
    --tag esbmc

python3.11 scripts/parse_esbmc.py --mode full --tag esbmc
```

- **Properties**: array bounds (CWE-119), pointer dereference (CWE-476), memory leaks (CWE-401), use-after-free (CWE-416)
- **Output**: `analysis/esbmc/`, `results/raw_csv/esbmc_summary.csv`, `results/raw_csv/esbmc_violations.csv`

#### Config B — With Overflow-Check (unwind=10, timeout=60s)

```bash
python3.11 scripts/run_esbmc.py \
    --mode full --jobs 8 --only all \
    --unwind 10 --timeout 60 \
    --tag esbmc_overflow

python3.11 scripts/parse_esbmc.py --mode full --tag esbmc_overflow
```

- **Additional property**: arithmetic overflow (CWE-190)
- **Output**: `analysis/esbmc_overflow/`, `results/raw_csv/esbmc_overflow_summary.csv`, etc.

#### Config C — Deep Unwind (overflow-check, unwind=20, timeout=120s)

```bash
python3.11 scripts/run_esbmc.py \
    --mode full --jobs 8 --only all \
    --unwind 20 --timeout 120 \
    --tag esbmc_deep

python3.11 scripts/parse_esbmc.py --mode full --tag esbmc_deep
```

- **Purpose**: Evaluate sensitivity to loop unwind depth; captures violations in deeper loop iterations
- **Output**: `analysis/esbmc_deep/`, `results/raw_csv/esbmc_deep_summary.csv`, etc.

#### ESBMC via run_full_analysis.py (alternative)

The orchestration script can run any ESBMC configuration after Steps 1–7:

```bash
# Config B via orchestrator
python3.11 scripts/run_full_analysis.py \
    --skip-extract --skip-tests --skip-cppcheck \
    --skip-clang-tidy --skip-sanitizers --skip-parse --skip-merge \
    --esbmc --esbmc-tag esbmc_overflow

# Config C via orchestrator
python3.11 scripts/run_full_analysis.py \
    --skip-extract --skip-tests --skip-cppcheck \
    --skip-clang-tidy --skip-sanitizers --skip-parse --skip-merge \
    --esbmc --esbmc-tag esbmc_deep --esbmc-unwind 20 --esbmc-timeout 120
```

#### ESBMC Output Files (per tag)

| File | Description |
|------|-------------|
| `results/raw_csv/{tag}_summary.csv` | One row per program: verdict, violation count, CWEs |
| `results/raw_csv/{tag}_violations.csv` | Per-violation detail with CWE classification |

| `results/raw_csv/{tag}_cross_reference.csv` | Three-way cross-reference: cppcheck × sanitizer × ESBMC |

## Troubleshooting

**Cppcheck version mismatch**: CWE mappings may differ between cppcheck versions. Use v2.19.0 for exact replication.

**Clang-tidy not found**: On Ubuntu, install via `sudo apt-get install clang-tidy-21`. The script expects the binary named `clang-tidy-21`.

**Sanitizer out-of-memory**: ASan increases memory usage ~2×. If a program OOMs under sanitizer, it is recorded as a sanitizer event. Ensure at least 16 GB RAM.

**Test timeout differences**: Minor variations in pass rates may occur on different hardware due to the 10-second timeout boundary. This does not affect sanitizer or static analysis results.

**ESBMC parse errors**: ESBMC cannot parse approximately 56.5% of contest programs (C++ features outside its frontend support). These are recorded as `PARSE_ERROR` and excluded from verification statistics.

**ESBMC timeouts**: ~18.2% of analyzable programs time out under Config A (60s). Config C (120s) reduces this. Timeouts are recorded but not counted as violations.

**ESBMC binary not found**: Ensure the binary is at `esbmc/bin/esbmc` relative to the repository root and is executable (`chmod +x esbmc/bin/esbmc`).
