# VulBench-CPP: Evaluating the Security of AI-Generated C++ Code

Replication package for the ICSME 2026 paper:

> **Evaluating the Security of AI-Generated C++ Code: An Empirical Comparison with Human Baselines**
> Saif Mahmud, Fadul Sikder, Yuede Ji, Zhang Haotian, Jeff (Yu) Lei
> University of Texas at Arlington & New Jersey Institute of Technology

## Overview

We introduce **VulBench-CPP**, a benchmark of **8,918 C++ programs** — 7,223 AI-generated by three open-weight LLMs and 1,695 human-written solutions across 851 competitive programming tasks from the CodeContests dataset. Each program is annotated with outputs from four verification tiers: functional correctness testing, static analysis (cppcheck, clang-tidy), dynamic analysis (ASan/UBSan), and bounded model checking (ESBMC).

## Research Questions

| RQ | Question | Key Finding |
|----|----------|------------|
| **RQ1** | How do vulnerability rates of AI-generated code compare to human-written code under multi-tier verification? | AI-generated code triggers runtime violations at **3.6× the rate** of human code (*z* = 9.28, *p* < 0.001) — a gap entirely concealed by static analysis, which reports comparable warning rates for both. |
| **RQ2** | Are vulnerability patterns reproducible across independent generations of the same model? | Within-model variance ≤ 1.8 pp across generations, confirming patterns reflect systematic model properties, not sampling artifacts. |
| **RQ3** | What vulnerability classes does each tier detect, and how do distributions differ between AI and human code? | Cross-tier agreement is near-zero (Jaccard ≈ 0.05): of 661 formally proven violations 598 are not triggered by sanitizers; of 639 sanitizer-triggered programs 576 are not flagged by ESBMC. Each tier detects distinct, largely non-overlapping vulnerability classes. |

## Models

| Model | Programs |
|-------|---------|
| Gemma 3 27B IT | 2,238 |
| LLaMA 3.3 70B Instruct | 2,496 |
| Qwen 2.5 Coder 32B Instruct | 2,489 |
| **Human baseline** (CodeContests) | 1,695 |

All models were accessed via the OpenRouter API under zero-shot prompting with three independent generations per problem.

## Analysis Pipeline

| Tier | Tool | Purpose |
|------|------|---------|
| Functional testing | g++ 13.3.0 + test suites | Correctness evaluation (10s timeout) |
| Static analysis | cppcheck 2.19.0 | CWE detection and code quality (30s timeout) |
| Static analysis | clang-tidy 21 | Path-sensitive security diagnostics |
| Dynamic analysis | ASan / UBSan | Runtime memory-safety violation detection |
| Formal verification | ESBMC v8.0.0 | Bounded model checking (SMT-based) |

VulBench-CPP is the first C++ benchmark to combine an uncontaminated human reference baseline with four-tier verification, addressing the critical evidence gap left by prior static-only or Python-centric datasets.

## Quick Start

```bash
# Install dependencies
pip install pandas numpy scipy matplotlib seaborn pyarrow jupyter

# Run Steps 1–7 (static + dynamic)
python3.11 scripts/run_full_analysis.py

# Add ESBMC formal verification (Step 8) — three configurations
# Config 1: overflow-check, unwind=10, timeout=60s
python3.11 scripts/run_full_analysis.py --skip-extract --skip-tests \
    --skip-cppcheck --skip-clang-tidy --skip-sanitizers --skip-parse --skip-merge \
    --esbmc --esbmc-tag esbmc_overflow

# Config 2: overflow-check, deeper unwind=20, timeout=120s
python3.11 scripts/run_full_analysis.py --skip-extract --skip-tests \
    --skip-cppcheck --skip-clang-tidy --skip-sanitizers --skip-parse --skip-merge \
    --esbmc --esbmc-tag esbmc_deep --esbmc-unwind 20 --esbmc-timeout 120

# Or run individual steps — see REPLICATION.md for details
```
