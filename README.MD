# Beyond Static Analysis: Why Algorithmic AI Code Generation Requires Runtime Sanitization

Replication package for the empirical study characterizing vulnerability patterns in C++ code generated by large language models.

## Overview

This study analyzes **8,918 C++ programs** (7,223 AI-generated + 1,695 human-written) across 851 competitive programming tasks from the CodeContests dataset. We combine static analysis with dynamic runtime sanitization to characterize vulnerability patterns.

**Key finding**: AI-generated code triggers runtime memory-safety violations at **3.6x** the rate of human-written code (9.3% vs 2.6%), a gap invisible to static analysis alone.

## Models

- **Gemma 3 27B IT**
- **LLaMA 3.3 70B Instruct**
- **Qwen 2.5 Coder 32B Instruct**

## Baseline

- **Human C++ solutions** from google-deepmind/code_contests (two reference implementations per problem)

## Analysis Pipeline

| Tier | Tool | Purpose |
|------|------|---------|
| Functional testing | g++ 13.3.0 + test suites | Correctness evaluation (10s timeout) |
| Static analysis | cppcheck 2.19.0 | CWE detection and code quality (30s timeout) |
| Static analysis | clang-tidy 21 | Path-sensitive security diagnostics |
| Dynamic analysis | ASan / UBSan | Runtime memory-safety violation detection |
